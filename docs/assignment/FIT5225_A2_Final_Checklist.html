2. System Scope and Architecture

DoneIDRequirementHow this requirement is found from context
A1 Build Aussie EcoLens as a multi-cloud online storage system for wildlife media: store, organise, retrieve images/videos using auto-generated and manual tags. Spec p.1 background states the assignment aims to build a multi-cloud online storage system to store, organise, and retrieve media files based on auto-generated and manual tags.
A2 Use at least two major cloud providers, e.g., AWS plus GCP/Azure/Oracle. Spec p.1 says serverless application across at least two major cloud providers; Spec p.2 repeats multi-cloud solution across multiple providers.
A3 Use serverless compute, RESTful API, cloud storage, and database services across the providers. Spec p.2 says teams should leverage serverless compute, RESTful API, storage, and database services.
A4 End users can upload files to a public cloud storage bucket. Spec p.1 and p.2 describe uploading media files to public cloud storage / designated cloud storage bucket.
A5 After upload, automatically tag species, sort/move the file to the corresponding directory, and create a searchable database record. Spec p.1 states automatic tagging, automatic sorting/moving to the corresponding directory, and adding a DB record.
A6 Use a highly available database for detected tags and storage URLs. Spec p.2 says detected tags and file storage URL must be stored in a highly available database.

3. Authentication and Authorisation

DoneIDRequirementHow this requirement is found from context
B1 Use AWS Cognito for authentication and authorisation. Spec p.2 states Cognito must be used for user authentication/authorisation; Rubric p.1 awards full marks for Cognito handling auth workflow.
B2 Register new users with email address, first name, last name, and password. Spec p.2-3 and Rubric p.1 list these registration details.
B3 Support email verification and temporary password/change-password workflow for new users. Spec p.3 says Cognito emails new users to verify email and change temporary password; Rubric p.1 includes email verification.
B4 Provide sign-in/login and secure sign-out. Spec p.3 requires a login page and sign-out after authentication; Rubric p.1 marks sign-up/sign-in/sign-out securely.
B5 Detect unauthenticated users; block all pages and endpoints except sign-up; redirect unauthenticated users to sign-up. Spec p.2 says block access to all pages/endpoints except sign-up and redirect; Rubric p.1 awards access control/redirection marks.
B6 Protect upload, query, results-viewing, and sign-out services against unauthorised access. Spec p.3 says after login users can upload, query, view results, and sign out, and all these services must be protected.
B7 Fine-grained IAM/equivalent policies for file uploads, serverless function invocation, and database access. Spec p.3 says uploads, serverless functions, and DB access require fine-grained IAM/equivalent policies; Rubric p.1 marks uploads, DB access, and Lambda invocations.
B8 Avoid overly permissive IAM policies and handle cross-cloud token authorisation securely. Rubric p.1 penalises overly permissive roles and missing cross-cloud token handling; Spec p.2 highlights passing Cognito tokens to secondary cloud endpoints/functions.
B9 Consider AWS Academy IAM role limitations in the auth/permission design. Spec p.3 explicitly notes IAM role limitations in AWS Academy and asks teams to consider them.
B10 Login/sign-up pages may use Cognito Hosted UI or custom pages calling Cognito APIs. Spec p.3 allows Hosted UI or custom implementation.

4. Core File/Model Handling

DoneIDRequirementHow this requirement is found from context
C1 Design model loading/versioning so a new pretrained model version can be used without changing source code or Lambda/function code. Spec p.3 Model Handling section states model updates should be usable without changing source code/lambda function.
C2 Support file upload through RESTful API endpoint or cloud SDK. Spec p.3 says upload can be through RESTful API or directly using cloud SDKs; Rubric p.2 marks API/SDK upload.
C3 Every uploaded file must trigger an event and invoke a serverless function automatically. Spec p.3 says whenever a file is uploaded, system must trigger an event and invoke a serverless function; Rubric p.2 penalises manual triggers.
C4 Prevent duplicate uploads using a file checksum, not only file names. Spec p.3 requires checksum deduplication; Rubric p.2 says relying on names is partial only.
C5 For image uploads, generate thumbnails using a serverless function. Spec p.3 requires serverless thumbnail generation; Rubric p.2 awards thumbnail creation marks.
C6 Thumbnail generation must resize while maintaining aspect ratio and compress to reduce file size. Spec p.3 describes resizing while maintaining aspect ratio and compression; Rubric p.2 includes aspect ratio/compressed.
C7 Configure triggers and required execution/resource permissions for thumbnail functions. Spec p.3 expects triggers and execution-role permissions for thumbnail function.
C8 For tagging, a serverless function reads the uploaded file and detects species using the provided ML model. Spec p.3 says another serverless function should detect species using the ML model; Rubric p.2 marks serverless ML detection.
C9 Save file type, detected tag list, original file URL, and thumbnail URL for images in the database. Spec p.3 and Rubric p.2 require file type, tags, storage URLs for file and thumbnail.
C10 For videos, extract frames as images at exactly 1 image/frame per second; do not extract all frames. Spec p.3-4 says extract 1 image per second and do not extract all frames; Rubric p.2 marks 1 frame/sec.

5. Queries

DoneIDRequirementHow this requirement is found from context
D1 Provide protected RESTful APIs for all required queries. Spec p.2 and p.4 require RESTful API endpoints for searching tagged files.
D2 Tag-count query accepts JSON such as {"koala": 3} and returns files containing at least the minimum counts. Spec p.4 gives examples with minimum counts; Rubric p.2 marks counts/species query.
D3 Multi-tag count queries must use logical AND, not OR, across tags. Spec p.4 explicitly says logical AND, not OR; Rubric p.2 penalises OR.
D4 For tag-count query responses, return thumbnail URLs for matching images and full URLs for matching videos. Spec p.4 says response includes thumbnails for images and full URLs for videos.
D5 Support species query without counts, e.g., {"dingo"}, returning images/videos containing at least one instance of that species. Spec p.4 requires a species query without count.
D6 Support thumbnail URL query: input a thumbnail URL and return the corresponding full-size image URL. Spec p.4 and Rubric p.2 require thumbnail URL to full-size URL mapping.
D7 Support file-as-query: accept a file in an API call, detect its tags, and return database files containing that set of tags. Spec p.4 and Rubric p.3 require uploaded-file query with tag detection and matching DB URLs.
D8 Do not add or permanently store the uploaded query file used for file-as-query. Spec p.4 and Rubric p.3 explicitly require not permanently storing query file.
D9 Ensure query responses return correct working URLs, not broken mappings. Rubric p.2 emphasises returning correct URLs and penalises broken URLs.
D10 Query functions may trigger serverless functions that receive tag lists from the database. Spec p.4 states the query may require triggering a function that receives tag lists from the DB.

6. Data Management and Notifications

DoneIDRequirementHow this requirement is found from context
E1 Provide a POST API for manual bulk addition/removal of tags from files. Spec p.4 and Rubric p.3 require POST API and bulk tag editing.
E2 Manual tag-edit JSON must include a list of URLs, tags to modify, and operation key. Spec p.4 states JSON must include URLs, tags, and operation key.
E3 Use operation=1 for adding tags and operation=0 for removing tags. Spec p.4 and Rubric p.3 define 1=add and 0=remove.
E4 When removing tags, ignore tags not assigned to the file instead of failing. Spec p.4 and Rubric p.3 require ignoring tags not in deletion list/assigned tags.
E5 Bulk tag editing must work for multiple files, not only a single file. Rubric p.3 says partial if API works only for single files but fails on bulk.
E6 Delete API accepts a list of URLs and removes full images, thumbnails, videos, and all relevant database entries. Spec p.4 and Rubric p.3 require deletion from storage and DB.
E7 Bulk deletion must work correctly; do not leave storage or database orphan records. Rubric p.3 penalises deletion from DB but not storage or vice versa and bulk failures.
E8 Provide tag-based notifications when watched/specific tags are added or updated. Spec p.4 says users receive notifications when new images with specific species are added or updated; Rubric p.3 says watched tags added.
E9 Use AWS SNS or equivalent serverless messaging service, with specific tag filtering and working email formatting. Spec p.4 permits SNS/equivalent; Rubric p.3 penalises inconsistent triggers, weak filtering, or broken email formatting.

DoneIDRequirementHow this requirement is found from context

F9 UI should be professional and user-friendly. Rubric p.4 awards full marks for professional, user-friendly design.
F10 If no UI or partial UI is implemented, prepare flawless alternatives such as CLI, scripts, or Postman; without UI the UI section is capped at D/14 marks; with neither UI nor scripts, Section 3 receives 0. Spec p.5 and Rubric p.5 additional note state the cap and alternative demo methods.
